#문제 풀이
링크 
프로그래머스 무지의 먹방라이브 (링크 : https://school.programmers.co.kr/learn/courses/30/lessons/42891)

## 제한조건
주의 사항: 효율성 테스트 존재 (K는 최대 2 X 10^13, N은 최대 200,000)

## 시간 복잡도 분석 및 전략
두가지 방법으로 풀이가 가능
1. 우선순위 큐(Min-Heap)를 활용한 그리디 알고리즘 $O(N \log N)$
2. 이분 탐색(Parametric Search)을 활용한 방법 $O(N \log N)$ 

### 해결방안
위의 두 가지 방법 모두로 효율성 테스트 통과가 가능.
가장 먹는 데 시간이 적게 걸리는 음식부터 큐에서 꺼내며, 해당 음식을 다 먹을 때까지 걸리는 시간을 '남은 음식 개수'와 곱하여 K에서 한 번에 빼주는 방식으로 시간을 단축

### 예외케이스
더 이상 먹을 음식이 없는 경우: 주어지는 모든 음식 시간(food_times)의 총합보다 방송 중단 시간 K가 크거나 같은 경우임
방송이 재개되었을 때 먹을 음식이 없으므로 -1을 반환

### 고민했던 흔적들
1초마다 배열을 순회하며 -1을 해주는 방식은 O(K)가 되어 효율성 테스트(최대 2X 10^13초)를 절대 통과할 수 없음.
따라서 **"가장 빨리 다 먹게 되는 음식"**을 기준으로, 그 음식을 다 먹을 때까지 회전판이 도는 횟수를 한 번에 계산해서 K초에서 차감해야 함.
우선순위 큐 (Priority Queue) 적용(음식을 먹는 데 걸리는 시간, 음식의 원래 번호)를 객체로 묶어 우선순위 큐에 삽입. 
(시간이 적게 걸리는 순으로 정렬)(현재 큐에서 가장 적은 음식 시간 - 지금까지 먹은 시간)

- 남은 음식의 개수를 구함.이 값이 남은 방송 중단 시간 K보다 작거나 같다면, K에서 이 값을 빼고 큐에서 해당 음식을 제거.
- 만약 K보다 크다면, 더 이상 한 바퀴를 온전히 돌 수 없음을 의미하므로 반복문을 종료함.

- 남은 음식들의 순서 복원큐에 남아있는 음식들은 아직 다 먹지 못한 음식들임.
- 회전판은 번호가 증가하는 순서대로 돌아가므로, 남아있는 음식들을 '원래 음식 번호'를 기준으로 다시 오름차순 정렬함.
- 정렬된 리스트에서 K % (남은 음식의 개수) 번째 인덱스에 위치한 음식 번호가 최종 정답이 됨.
